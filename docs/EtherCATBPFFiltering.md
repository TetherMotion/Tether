# EtherCAT Socket Filtering with Classic BPF

Tether can attach a classic-BPF (`SO_ATTACH_FILTER`) program to its raw
`AF_PACKET` sockets so that non-EtherCAT traffic is rejected **in the
kernel**, before it ever reaches userspace. This eliminates wake-ups and
copying for broadcast storms, ARP, IP, and other background traffic on a
shared interface.

Programs are generated by `EtherCAT::CBPFProgramFactory`
(`include/tether/ethercat/CBPFProgramFactory.hpp`) and are plain data —
no `bpf()` syscall, no verifier interaction, and no privileges beyond
what the raw socket itself already requires (CAP_NET_RAW). Classic BPF
is internally translated to eBPF by the kernel, so there is no runtime
performance difference.

```cpp
auto prog = EtherCAT::CBPFProgramFactory::ethercatFilter();
CBPFProgramFactory::attach(fd, prog);          // SO_ATTACH_FILTER + SO_LOCK_FILTER
```

`attach()` returns `false` on non-Linux platforms or when the kernel
rejects the program; a failed attach is a soft failure — the socket
still works, it just receives everything.

## Filter modes

| Mode | Factory | Accepted |
|------|---------|----------|
| Default | `ethercatFilter()` | Untagged EtherType `0x88A4`; 802.1Q-tagged frames (any VID) whose inner EtherType is `0x88A4` |
| UDP | `ethercatFilterWithUdp(port)` | Above, plus IPv4/UDP with destination port `port` (default 34980 = `0x88A4`, ETG.1000.3), tagged or untagged |
| VLAN | `vlanFilter(vid)` / `vlanRangeFilter(lo, hi)` | **Only** 802.1Q frames with VID in range whose inner EtherType is `0x88A4` |

### VLAN mode rejects untagged traffic

When a VLAN encapsulation is active (`--encapsulation vlan:<vid>`), the
generated program accepts a frame **if and only if**:

1. its outer EtherType is `0x8100` (802.1Q), **and**
2. the VID field of the TCI matches the configured VLAN (PCP/DEI bits
   are masked out), **and**
3. the inner EtherType is `0x88A4` (EtherCAT) — or, when combined with
   `udp` (`--encapsulation vlan:1999,udp`), an IPv4/UDP datagram whose
   destination port is the configured EtherCAT UDP port.

Consequently, in VLAN mode the socket rejects:

- **untagged frames — including untagged EtherCAT** (`EtherType 0x88A4`
  directly on the wire),
- frames tagged with a different VID,
- matching-VID frames carrying non-EtherCAT payloads (ARP, IPv4, …),
- 802.1ad/QinQ frames (outer TPID `0x88A8`, or a second nested tag).

This is intentional: `--encapsulation vlan:N` means "the segment lives
inside VLAN N", so untagged traffic is by definition not ours.
Applications that need the untagged segment *and* a VLAN segment
concurrently should use two sockets (or the `CBPFSpec` API, below)
rather than the VLAN filter.

## UDP encapsulation (ETG.1000.3)

EtherCAT-over-UDP frames are `eth | IPv4 | UDP | EtherCAT`. The UDP
check verifies, in order:

- IP protocol == 17 (UDP),
- IHL ≥ 5 (then `MSH` computes the variable header length, so IPv4
  options are handled correctly),
- fragment offset == 0 (non-first fragments carry no UDP header and are
  dropped; first fragments with MF set are accepted),
- UDP **destination** port == 34980 (or the configured port).

Truncated frames are rejected implicitly: any out-of-bounds load faults
in the kernel interpreter and the packet is dropped.

## Custom policies

`CBPFSpec` exposes the individual switches:

```cpp
EtherCAT::CBPFSpec s;
s.untagged_ethercat = true;    // EtherType 0x88A4
s.untagged_udp      = true;    // untagged IPv4/UDP :34980
s.tagged_ethercat   = true;    // 0x8100 + inner 0x88A4
s.tagged_udp        = true;    // 0x8100 + inner IPv4/UDP
s.vlan_range        = EtherCAT::CBPFVlanRange{100, 200}; // restrict tagged VIDs
s.vlan_tpid         = 0x88A8;  // e.g. 802.1ad instead of 802.1Q
auto prog = EtherCAT::CBPFProgramFactory::build(s);
```

`build()` returns an empty vector for a spec that accepts nothing; pass
`--encapsulation vlan:…` values through `vlanFilter()`/
`vlanRangeFilter()` which validate `vid ≤ 4095` and `lo ≤ hi`.

## Examples

All Linux host examples expose `--encapsulation` (see
[EtherCATEncapsulation](EtherCATEncapsulation.md) for the full token
grammar and the `setupEncapsulation()` API):

```
list_slaves -i eth0                             # raw EtherCAT
list_slaves -i eth0 --encapsulation vlan:1999   # tagged VLAN 1999 only
list_slaves -i eth0 --encapsulation vlan:100-200,vlantx:150
list_slaves -i eth0 --encapsulation udp         # EtherCAT-over-UDP :34980
list_slaves -i eth0 --encapsulation vlan:1999,udp
```

The token grammar is `raw|none`, `vlan:<vid>`, `vlan:<lo>-<hi>`,
`vlan:any`, `vlantx:<vid|off>`, `udp[:<port>]`, comma-separated.
`Tether::Examples::setupEncapsulation()`
(`examples/common/ExampleHelpers.hpp`) applies a parsed
`EncapsulationConfig` in one call: it attaches the matching cBPF
program, enables EtherCAT-over-UDP on the master, and wires the
`VLANRouter` + RX callback, returning the `NetworkInterface` the master
should `start()` on.

## Testing

`cbpfExecute(prog, data, len)` is a user-space interpreter implementing
kernel classic-BPF semantics (out-of-bounds load → drop, div-by-zero →
drop, etc.). `tests/ethercat/test_cbpf_program_factory.cpp` runs
synthesized packets through every generated program and additionally
attaches programs to an `AF_UNIX` datagram pair so the kernel itself
verifies accept/reject behaviour without requiring `CAP_NET_RAW`.

## Relationship to the cyclic-channel demux

`CyclicChannel` uses a separate, specialized filter
(`cyclicChannelBpfProgram()`) that additionally demultiplexes on the
first datagram's `idx` byte to split cyclic from asynchronous traffic.
`CBPFProgramFactory` produces the general-purpose "is this EtherCAT
traffic meant for me" ingress filter; the two can be composed (a socket
may only carry one filter — combine policies in a single program rather
than stacking).
