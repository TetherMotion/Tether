# EtherCAT Socket Filtering with Classic BPF

Tether can attach a classic-BPF (`SO_ATTACH_FILTER`) program to its raw
`AF_PACKET` sockets so that non-EtherCAT traffic is rejected **in the
kernel**, before it ever reaches userspace. This eliminates wake-ups and
copying for broadcast storms, ARP, IP, and other background traffic on a
shared interface.

Programs are generated by `EtherCAT::CBPFProgramFactory`
(`include/tether/ethercat/CBPFProgramFactory.hpp`) and are plain data —
no `bpf()` syscall, no verifier interaction, and no privileges beyond
what the raw socket itself already requires (CAP_NET_RAW). Classic BPF
is internally translated to eBPF by the kernel, so there is no runtime
performance difference.

```cpp
auto prog = EtherCAT::CBPFProgramFactory::ethercatFilter();
CBPFProgramFactory::attach(fd, prog);          // SO_ATTACH_FILTER (SO_LOCK_FILTER opt-in)
```

`attach()` returns `false` on non-Linux platforms or when the kernel
rejects the program; a failed attach is a soft failure — the socket
still works, it just receives everything.

## Filter modes

| Mode | Factory | Accepted |
|------|---------|----------|
| Default | `ethercatFilter()` | Untagged EtherType `0x88A4`; 802.1Q-tagged frames (any VID) whose inner EtherType is `0x88A4` |
| UDP | `ethercatFilterWithUdp(port)` | Above, plus IPv4/UDP with destination port `port` (default 34980 = `0x88A4`, ETG.1000.3), tagged or untagged |
| VLAN | `vlanFilter(vid)` / `vlanRangeFilter(lo, hi)` | **Only** 802.1Q frames with VID in range whose inner EtherType is `0x88A4` |

### VLAN mode rejects untagged traffic

When a VLAN encapsulation is active (`--encapsulation vlan:<vid>`), the
generated program accepts a frame **if and only if** it carries a
matching 802.1Q tag (inline or kernel-stripped, see below) whose VID
matches the configured VLAN (PCP/DEI bits are masked out) **and** its
inner EtherType is `0x88A4` (EtherCAT) — or, when combined with `udp`
(`--encapsulation vlan:1999,udp`), an IPv4/UDP datagram whose
destination port is the configured EtherCAT UDP port.

Consequently, in VLAN mode the socket rejects:

- **untagged frames — including untagged EtherCAT** (`EtherType 0x88A4`
  directly on the wire),
- frames tagged with a different VID,
- matching-VID frames carrying non-EtherCAT payloads (ARP, IPv4, …),
- 802.1ad/QinQ frames (outer TPID `0x88A8`, or a second nested tag).

This is intentional: `--encapsulation vlan:N` means "the segment lives
inside VLAN N", so untagged traffic is by definition not ours.
Applications that need the untagged segment *and* a VLAN segment
concurrently should use two sockets (or the `CBPFSpec` API, below)
rather than the VLAN filter.

### Kernel VLAN untagging (rx-vlan-offload)

On RX, Linux removes the 802.1Q tag **before** packet sockets see the
frame — either in the NIC (rx-vlan-offload) or in the generic
`__netif_receive_skb_core` untag path, which runs unconditionally before
packet taps on modern kernels. An inbound tagged frame therefore arrives
at a socket with the *inner* EtherType at offset 12 and the tag only in
skb metadata — `PACKET_AUXDATA`/`tpacket_auxdata` for `recvmsg`, and
`SKF_AD_VLAN_TAG`/`SKF_AD_VLAN_TAG_PRESENT` ancillary loads for cBPF
(the same mechanism libpcap's `vlan` primitive uses).

The generated programs handle both representations:

- `[12] == 0x8100` → inline tag (self-TX `PACKET_OUTGOING` copies still
  carry the tag inline; useful for local loopback traffic).
- `[12] == 0x88A4`/`0x0800` → consult `SKF_AD_VLAN_TAG_PRESENT`; when a
  stripped tag is present, `SKF_AD_VLAN_TAG` supplies the TCI for the
  VID/range check. When absent, the frame is genuinely untagged and the
  untagged legs apply — so VLAN mode still rejects it.

`LinuxEthernet` (`PACKET_AUXDATA` + `recvmsg`) mirrors this on the
userspace side: instead of reinserting the tag into the frame buffer it
surfaces the stripped TCI through `RxFrameInfo` (`vlanTagPresent`,
`vlanId`, `vlanPriority`), and `VLANRouter::processRxFrame` accepts that
VID out-of-band — a stripped frame is already decapsulated, so the whole
path needs no copying at all. Note that tcpdump/libpcap *reconstruct*
stripped tags for display — tcpdump output is not proof of the bytes a
cBPF program sees.

## UDP encapsulation (ETG.1000.3)

EtherCAT-over-UDP frames are `eth | IPv4 | UDP | EtherCAT`. The UDP
check verifies, in order:

- IP protocol == 17 (UDP),
- IHL ≥ 5 (then `MSH` computes the variable header length, so IPv4
  options are handled correctly),
- fragment offset == 0 (non-first fragments carry no UDP header and are
  dropped; first fragments with MF set are accepted),
- UDP **destination** port == 34980 (or the configured port).

Truncated frames are rejected implicitly: any out-of-bounds load faults
in the kernel interpreter and the packet is dropped.

## Custom policies

`CBPFSpec` exposes the individual switches:

```cpp
EtherCAT::CBPFSpec s;
s.untagged_ethercat = true;    // EtherType 0x88A4
s.untagged_udp      = true;    // untagged IPv4/UDP :34980
s.tagged_ethercat   = true;    // 0x8100 + inner 0x88A4
s.tagged_udp        = true;    // 0x8100 + inner IPv4/UDP
s.vlan_range        = EtherCAT::CBPFVlanRange{100, 200}; // restrict tagged VIDs
s.vlan_tpid         = 0x88A8;  // e.g. 802.1ad instead of 802.1Q
auto prog = EtherCAT::CBPFProgramFactory::build(s);
```

`build()` returns an empty vector for a spec that accepts nothing; pass
`--encapsulation vlan:…` values through `vlanFilter()`/
`vlanRangeFilter()` which validate `vid ≤ 4095` and `lo ≤ hi`.

## Examples

All Linux host examples expose `--encapsulation` (see
[EtherCATEncapsulation](EtherCATEncapsulation.md) for the full token
grammar and the `setupEncapsulation()` API):

```
list_slaves -i eth0                             # raw EtherCAT
list_slaves -i eth0 --encapsulation vlan:1999   # tagged VLAN 1999 only
list_slaves -i eth0 --encapsulation vlan:100-200,vlantx:150
list_slaves -i eth0 --encapsulation udp         # EtherCAT-over-UDP :34980
list_slaves -i eth0 --encapsulation vlan:1999,udp
```

The token grammar is `raw|none`, `vlan:<vid>`, `vlan:<lo>-<hi>`,
`vlan:any`, `vlantx:<vid|off>`, `udp[:<port>]`, comma-separated.
`Tether::Examples::setupEncapsulation()`
(`examples/common/ExampleHelpers.hpp`) applies a parsed
`EncapsulationConfig` in one call: it attaches the matching cBPF
program, enables EtherCAT-over-UDP on the master, and wires the
`VLANRouter` + RX callback, returning the `NetworkInterface` the master
should `start()` on.

## Testing

`cbpfExecute(prog, data, len)` is a user-space interpreter implementing
kernel classic-BPF semantics (out-of-bounds load → drop, div-by-zero →
drop, etc.). `tests/ethercat/test_cbpf_program_factory.cpp` runs
synthesized packets through every generated program and additionally
attaches programs to an `AF_UNIX` datagram pair so the kernel itself
verifies accept/reject behaviour without requiring `CAP_NET_RAW`.

## Relationship to the cyclic-channel demux

`CyclicChannel` uses a separate, specialized filter
(`cyclicChannelBpfProgram()`) that additionally demultiplexes on the
first datagram's `idx` byte to split cyclic from asynchronous traffic.
`CBPFProgramFactory` produces the general-purpose "is this EtherCAT
traffic meant for me" ingress filter; the two can be composed (a socket
may only carry one filter — combine policies in a single program rather
than stacking).

## Proxy forwarding band (external PDO source)

When `Master::setProxyForwarding()` is enabled, a contiguous datagram-idx
band below `0x9C` is reserved for a foreign EtherCAT master reachable
over a second NIC. Three composed programs implement the contract:

- **Bus socket** (bound to the EtherCAT interface): `encap ∧ idx∈band` —
  only slave responses to injected PDO datagrams reach the forwarder.
- **Proxy forward socket** (bound to the proxy interface):
  `untagged+tagged ECAT ∧ idx∈band` — candidate frames for injection.
- **Proxy monitor socket** (bound to the proxy interface):
  `untagged+tagged ECAT ∧ idx∉band` — out-of-band EtherCAT frames are
  ignored, counted (`ProxyForwardStats::out_of_band`) and logged.

The async wire socket additionally gains a deny clause
(`CBPFSpec::first_idx_deny`) so band frames can never reach the master's
parser — with the cyclic mirror up the composed program is
`encap ∧ idx∉fastpath ∧ idx∉band`, otherwise `encap ∧ idx∉band`.

BPF only keys on the FIRST index; before injection the forwarder walks
the whole datagram chain (`ProxyForwarder::frameIsInBandPdo`) requiring
every datagram to be a logical command (LRD/LWR/LRW — the PDO commands)
carrying an in-band index, so an external source cannot inject
register/mailbox traffic or collide with master's own index space.
`PACKET_IGNORE_OUTGOING` on all three sockets prevents forward loops.

A second, optional userspace layer (`ProxyPdoFilter`) whitelists WHAT
the datagrams may touch inside their logical address space — classic
BPF cannot express it:

- `ProxyPdoAccessRule` grants read and/or write over a logical-address
  window; every byte of every datagram's span must be covered (LRD →
  read, LWR → write, LRW → both, grants union across rules).
- `ProxyPdoValueRule` constrains write payloads per cell:
  `(value & mask) == expected` on a 1..8-byte little-endian field;
  multiple rules on the same cell are OR'd (enumerated whitelist),
  different cells AND.  A datagram covering only part of a constrained
  cell is rejected — a fragment cannot prove the value.

When `ProxyForwardConfig::filter` is unset the whitelist is
**auto-generated from the PDO map** at forwarder start
(`Master::buildProxyPdoFilter`): one window per mapped PDO region —
per-PDO granularity for multi-PDO slaves, aggregate Rx/Tx windows for
single-PDO slaves.  `ProxyForwardConfig::pdo_selection` restricts the
set (`slaves`, `pdo_indexes`, `include_outputs`/`include_inputs`) and
`bidirectional` selects the capability model — every window rw (the
default; needed for LRW datagrams spanning input+output regions) or
direction-split (outputs write-only, inputs read-only).  An empty PDO
map generates zero windows → deny-all until the map exists.  Setting
`filter` explicitly bypasses generation entirely.  Rejected frames
bump `ProxyForwardStats::filtered`.

### UDP-encapsulated input (ETG.1000.3)

`ProxyForwardConfig::udp_input_port` (default 0 = off) opens an
additional UDP listener bound to the proxy interface.  A UDP datagram
whose payload is a bare EtherCAT frame — `[EtherCAT frame header]
[datagrams]`, no Ethernet header — is decapsulated, wrapped in a
synthesised Ethernet header (broadcast dst, bus-interface src MAC, plus
an 802.1Q tag carrying `tx_vlan` when the wire is VLAN-encapsulated),
and run through the same index-band + PDO + ACL validation as raw
proxy-interface frames.  Slave responses are re-encapsulated and
`sendto()`'d back to the last-seen UDP peer — a single UDP source at a
time is supported.  This path is independent of the master's wire
encapsulation mode: it only changes how the *external source* reaches
the forwarder.

### Lab setup without EtherCAT hardware (veth pairs)

Two veth pairs emulate the two links; the "slave" end can be any EtherCAT
echo responder (see `tests/ethercat/test_proxy_integration.cpp` for a
complete runnable setup):

```sh
# Pair A stands in for the bus, pair B links Tether to the client.
ip link add pxe0 type veth peer name pxe1      # bus:   Tether <-> slaves
ip link add pxp0 type veth peer name pxp1      # proxy: Tether <-> client
ip link set pxe0 up; ip link set pxe1 up
ip link set pxp0 up; ip link set pxp1 up
# Only needed for the UDP input path:
ip addr add 10.99.0.1/24 dev pxp0
ip addr add 10.99.0.2/24 dev pxp1

# Tether: cfg.iface = "pxe0", proxy.ifname = "pxp0".
# Client: raw  → ./ecat_proxy_external_source pxp1
#         udp  → ./ecat_proxy_external_source pxp1 --udp 10.99.0.1

# Cleanup (deleting one end drops the pair):
ip link del pxe0; ip link del pxp0
```

`examples/ecat_proxy_external_source.cpp` is a standalone client
(POSIX sockets only) that injects a proxy-band LRW datagram and prints
the echoed response — usable as raw EtherCAT frames on the proxy
interface or as ETG.1000.3 UDP datagrams via `--udp`.  The
`ProxyIntegration` gtest suite exercises the same topology end-to-end
and skips cleanly without CAP_NET_ADMIN/CAP_NET_RAW.
